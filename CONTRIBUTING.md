# Contributing

Thank you for your interest in contributing to the Documentation-First Development Framework!

## How to Contribute

### Reporting Issues

- Use the GitHub issue tracker
- Include clear reproduction steps
- Specify which documents are affected

### Suggesting Improvements

- Open an issue to discuss the change first
- Explain the problem and proposed solution
- Consider impact on existing users

### Pull Requests

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/improvement`)
3. Make your changes
4. Ensure documentation is consistent
5. Submit a pull request

## Guidelines

### Documentation Style

- Use `<!-- AI: -->` HTML comments for instructional guidance
- Include Related Documents section in each planning doc
- Include AI Agent Instructions section with Quality Checklist
- Keep content stack-agnostic (or clearly label examples)

### Commit Messages

```
type: short description

Longer description if needed.
```

Types: `feat`, `fix`, `docs`, `refactor`, `chore`

## Code of Conduct

Be respectful and constructive. We're all here to build better tools.
